# Происхождение записей периметра

DomainScope сохраняет **происхождение** каждого домена и IP — откуда он узнал
о записи и через какого родителя. Из этих данных строится **цепочка
обнаружения**, которая уходит в Hub вместе с каждой находкой. Это нужно, чтобы:

- понимать, почему DomainScope считает тот или иной актив «нашим»;
- разбирать ложные срабатывания (parking, CDN, общий хостинг, дочерние компании);
- решать, нужен ли актив в периметре.

## Где это видно в Hub

### Цепочка обнаружения на карточке находки

Цепочка показывается на карточке находки DomainScope (Продукт → Находки →
находка) в блоке **«Цепочка обнаружения»**. Каждый шаг — тип источника и
значение, вложенный шаг — то, через что актив был найден. Например:

```
config: example.com
└─ subfinder: api.example.com
   └─ dns_resolve: 192.0.2.10
      └─ nmap: 192.0.2.10:443
```

Если к одному адресу ведёт несколько доменов, цепочек несколько — по одной на
каждый путь. Данные приходят в отчёте SARIF (свойство `trails` результата);
сама цепочка в Hub только отображается, кнопок действий у неё нет.

### Решения по периметру принимаются в разделе «Скоуп»

Действий над происхождением как таковым нет — решения принимаются над записями
периметра и предложениями сканера, в веб-интерфейсе Hub: проект → Скоуп.

| Что нужно | Где | Действие |
| --- | --- | --- |
| Принять или отклонить находку сканера в периметр | Скоуп → «Предложения» | одобрить и включить, одобрить и исключить, отклонить |
| Убрать домен со всем поддеревом насовсем | Скоуп → «Домены» → «Добавить запись» | запись **исключения** на нужном уровне — исключение `example.org` закрывает и все поддомены |
| Временно убрать запись | Скоуп → «Адреса» или «Домены» | удалить или отключить запись включения |
| Вернуть отключённую запись | Скоуп → «Деактив. (адреса)» или «Деактив. (домены)» | «Восстановить» |
| Посмотреть, что сканер реально видит | Скоуп → «Инвентарь» | пары домен ↔ IP |

Подробно экраны и смысл решений описаны в разделе
[Связка DomainScope и Hub](perimeter-integration.md#предложения-расширить-периметр).

## Типовые сценарии

### Сценарий A: DomainScope сканирует «не наш» домен

1. Откройте находку и посмотрите блок «Цепочка обнаружения»: из какой зоны и
   каким способом пришёл домен.
2. Если домен пришёл через `subfinder` или `tls_san` от чужой зоны —
   добавьте в Скоупе запись **исключения** на этот домен или на его зону.
   Исключение блокирует домен в базе DomainScope на следующем цикле
   обнаружения, а одобрение исключения из предложения сразу закрывает
   открытые находки по нему.
3. Если домен пришёл через `netbox_dns` — уберите зону из view NetBox DNS или
   поставьте ей тег `ignore-scan`.
4. Если адрес пришёл через `netbox_import` — снимите с него тег
   `DOMAINSCOPE_NETBOX_TAG` в NetBox или поставьте `ignore-scan`.

### Сценарий B: свежее обнаружение, нужно одобрить

1. Скоуп → «Предложения» — список того, что предложил сканер.
2. Для каждого: одобрить и включить, одобрить и исключить либо отклонить.
3. Одобренное как включение со следующего цикла обнаружения сканируется.

### Сценарий C: пропадают домены, которые раньше сканировались

1. Проверьте Скоуп → «Деактив. (домены)»: домены из периметра, переставшие
   резолвиться, Hub отключает с пометкой «не резолвится», и они там видны.
2. Проверьте, что домен жив (`dig <домен>`).
3. Вернувшийся домен Hub включит обратно сам, когда сканер увидит его снова
   резолвящимся. Отключённый вручную — только через «Восстановить».

### Сценарий D: приватные IP в SARIF, нужны только публичные

Это решается не через происхождение, а через фильтр сканера:

```ini
DOMAINSCOPE_SARIF_IP_SCOPE=public   # all / public / private
```

См. [Управление сканерами DomainScope](domainscope-scanners.md).

## Источники происхождения

Домены (`domains.source` в базе DomainScope):

| Source         | Что значит                                            |
| -------------- | ----------------------------------------------------- |
| `config`       | Прописан в `DOMAINSCOPE_DOMAINS` или YAML-конфиге     |
| `subfinder`    | Найден через subfinder (поддомены исходной зоны)      |
| `netbox_dns`   | Зона из view NetBox DNS                               |
| `scope_entry`  | Включение из периметра Hub                            |
| `tls_san`      | Извлечён из альтернативных имён TLS-сертификата на просканированном порту |

IP-адреса:

| Source          | Что значит                                  |
| --------------- | ------------------------------------------- |
| `netbox_import` | Импортирован из NetBox IPAM (в цепочке — вместе с тегами NetBox) |
| `dns_resolve`   | Получен DNS-резолвингом обнаруженного домена |
| `scope_entry`   | Подсеть из периметра Hub                     |

В цепочке встречаются ещё шаги сканеров (`nmap`, `nuclei`, `openvas`, `tlsx`) и
`unknown_parent` — родитель, о котором в базе не осталось записи.

Значений `discovery`, `netbox` и `manual` в происхождении нет.

!!! warning "Известное ограничение: домены Hub, прочитанные при старте, помечаются как `config`"
    При запуске воркер читает домены из периметра Hub и добавляет их к списку
    из конфигурации. Поэтому в цепочке они получают метку `config`, а не
    `scope_entry`; `scope_entry` получают только домены, добавленные в
    периметр после запуска воркера. Исправление отслеживается в
    [DomainScope#6](https://gitlab.com/hub_infosec/DomainScope/-/work_items/6).

## Отклонение и исключение — разные решения

**Отклонённое предложение возвращается.** Сканер присылает те же кандидаты
каждый цикл, и Hub переводит отклонённое предложение обратно в ожидание —
оно снова появится во вкладке «Предложения» на следующем цикле обнаружения.

Чтобы домен больше не предлагался и не сканировался, нужна запись
**исключения**: одобрите предложение как исключение или добавьте исключение
вручную. Кандидатов под активным исключением воркер отсекает сам и в Hub не
отправляет.

Отдельно от предложений: запись периметра, отключённая пользователем, не
включается обратно ни синхронизацией с NetBox, ни отчётом сканера о резолве —
вернуть её можно только кнопкой «Восстановить».
